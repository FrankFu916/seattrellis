可行性诊断：问题列表 + 高亮 / 向导式修复 / 内联诊断

真实任务：系统给出候选方案 C（总分 81.5，2 项硬规则违反）。教师需要快速理解「哪里错、为什么错、怎么改」。三方案展示同一份诊断数据的三种串联方式。

数据契约（§6.5 已冻结）：诊断来自 Rust audit 报告——hard_constraint_summary（all_satisfied / checked_rule_count / violation_count / witnesses）+ 七维软目标 breakdown + missing_data + suggested_actions（message_key + args 本地化）。本决策只冻结呈现与操作串联。

左侧问题清单（严重级排序），右侧座位图联动高亮；点问题 → 定位相关学生/座位。

方案 C · 2 项硬规则违反
座位图 红 = 硬规则违反 · 黄 = 建议
试一下：点击左侧任一问题，右侧对应座位高亮；「修复」按钮逐个执行（Rust editing 命令 + validator 复核）。
优势问题全景 + 空间定位并行；严重级排序引导注意力；修复入口集中（一键/逐个）；实现简单可靠。
代价列表与画布需要「双向联动」状态管理；小屏下列表挤压画布；问题多时（10+）列表滚动负担。
B
向导式修复
一次只处理一个问题：读问题 → 看定位 → 点修复 → 验证通过 → 进入下一个；顶部显示修复进度。
localhost:8765/class-302/repair
问题 1 / 3 · HARD 固定座位规则被违反 修好后自动进入下一项
学生丁001（STU001）应固定于 R1C1，实际在 R1C2
此规则为 HARD：不修复则方案不可用。R1C1 当前为空座，可直接移回。
修复动作 = Rust editing 命令（swap），执行后经独立 validator 复核才显示「通过」。
定位 R1C2（学生丁001）→ R1C1（空）
向导强制线性推进，避免「修了一个、忘了下一个」；每步结束给出 validator 复核结果。
优势认知负担最低——一次一个决定；修复进度可视化（顶部进度条）；最不易漏修；适合硬规则违规较多的场景。
代价问题多时步骤冗长；「跳过」语义需要明确（记入待办还是忽略）；无全局视图，教师难以评估总体状况。

违规/建议直接标在座位上（红/黄徽章），点击座位弹出诊断卡；名单侧同样内联标注。
