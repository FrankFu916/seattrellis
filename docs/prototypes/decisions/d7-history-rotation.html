Decision D7 · 计划 §7.1 项 7 / §7.4

历史 / 轮换模型：时间线 / 版本列表 / 周期计划

真实任务：初二（3）班已按每两周一次轮换运行 3 期。教师想回答：「上期谁坐在谁旁边？」「这期为什么这样轮换？」「能不能把 4 期轮换一起生成、批量保存？」——三个变体给出三种「历史是什么」的心智模型。

领域约束（已冻结）：轮换计划由 Rust 生成（每期独立求解、seed 逐期推进、历史快照参与公平轮换与近期邻座评估）；历史参与 fairness/avoid_recent_neighbors 评分（§0.2）；批量轮换结果可批量保存/导出（§7.4）；快照文件（v1.x）必须持续可读。

时间线强调「沿时间发生了什么」；与历史报告（history-report）数据契约一致。
优势直观回答「过去发生了什么」；时间顺序自然；每期变更摘要可读；适合叙事性回顾。
代价「回看某期完整座位」需要点击展开（多一步）；多期对比（第 1 vs 第 3 期）缺乏并排能力；对「规划未来轮换」帮助有限。

「对比版本」调用 Rust 差分（assignment distance + 评分对比），与候选比较（D5）共用比较组件。
版本模型与「快照文件 + 项目」存储模型最贴近（每个版本 = 一个 snapshot 文档）。
优势「版本」操作语义清晰：查看/对比/恢复/导出；与快照存储模型一一对应，实现成本最低；误操作可恢复（§7.4 快速恢复最近班级）。
代价弱化「时间/轮换」概念——历史仅作为版本堆叠，教师需自己记忆轮换节奏；「恢复」与「回退」语义需确认是否影响历史链。

代价每期小图在 60 人班级上信息密度不足（需缩放）；「历史回顾」叙事弱于时间线；与版本模型（B）的互操作需要设计（计划 vs 版本如何互相引用）。
