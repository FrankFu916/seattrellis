Decision D4 · 计划 §7.1 项 4

快速排座 vs 高级模式：默认隐藏哪些技术参数

真实任务：李老师只想「按班级现有规则再排一次，出 5 个方案挑一个」；同事王老师则想精确控制随机种子、候选数、每期轮换预算与各目标权重。两种方案展示同一操作的两种信息密度。

结果能力（§7.6 可复现性）：无论哪种模式，用户都必须能看到并导出本次结果的 seed、solver/build、规则版本、history range、candidate id，并能复制复现信息；「生成新 seed」必须易得。默认隐藏 ≠ 不可见。
A
默认精简（快速模式）
生成面板只暴露 3 个问题：用哪套规则？生成几个方案？本轮想优先什么？其余全部折叠。
localhost:8765/class-302/generate
席序· 生成方案 快速高级
💡 按班级当前规则（1 条硬规则 + 1 个目标）直接生成即可——如需调整请先到「规则」页。
规则集：初二（3）班 当前规则
生成几个候选方案？
本轮优先
「平衡」= 按规则权重均衡优化；其余选项调整内部权重组合。
高级选项：种子 / 求解预算 / 候选去重 / 历史范围 →
结果页仍会显示并导出：seed、solver/build、规则版本、history range、candidate id（§7.6）
「快速」模式不隐藏任何结果信息，只隐藏输入参数；默认值来自 Rust 端能力目录（candidate 1–20、seed 自动）。
优势90% 教师 90% 场景只有 3 个问题；默认参数由产品团队在 M4 验证后冻结（seed 随机、candidates 5）；降低首次使用挫败感。
代价高级用户每次要展开；「本轮优先」的语义需产品定义清楚（内部映射到权重预设）；默认值选错时排查成本高。
B
默认展开（高级模式）
生成面板直接列出全部参数：规则集、候选数、种子、求解预算、去重、历史范围、各目标权重。

想少点选项？→
参数名与 Rust 契约一一对应：seed / time-limit / candidates / exclude-… / history-range；UI 仅做输入级校验。
优势可复现性零摩擦（§7.6）；高级用户无需「展开」；与 CLI 参数语义一一对应，测试与文档成本最低。
代价新手面对 7+ 参数不知所措；「权重 JSON」门槛高；误改参数后结果差异难以归因。
