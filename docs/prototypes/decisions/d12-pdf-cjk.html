PDF CJK 字体策略：嵌入全字体 / 子集嵌入 / 系统字体 fallback

真实任务：导出 PDF 座位表必须正确显示中文姓名。当前 v1 fallback 到座位号（学生名丢失）。三种字体策略决定 PDF 质量与安装包体积。

不可违反约束：v2 final 安装包 5–20MB 是 release gate（不得靠砍功能达标）；CJK 姓名在 PDF 中必须可读（教师核对名单用）；Rust 侧 PDF 渲染路径保持轻依赖（最小 OOXML/PDF writer 政策，§5.6）。
A
嵌入全字体
把完整 CJK 字体（如思源黑体/Noto Sans CJK 全字符集）打进 PDF/安装包。

安装包 +10–15 MB
Noto Sans CJK 全字符集约 10–20MB；PDF 中每个文档都携带完整字体子集外的全部字形。
字形 100% 正确，任意字符可显示；但安装包体积压力大（10–15MB 字体 + 其余组件可能触碰 20MB 上限）。
优势实现最简单（直接嵌入）；任意生僻字/姓名可显示；PDF 在任何设备一致渲染。
代价安装包体积逼近 release gate 上限（5–20MB）；PDF 文件本身变大；字体许可与分发需核查（OFL 允许，但要归档）。
B
子集嵌入
只把本次文档用到的字形（姓名/标题/常用字）嵌入 PDF；安装包只带精简子集字体或运行时裁剪。

安装包 +0.5–2 MB
PDF 内嵌子集 ≈ 文档实际用字（通常 100–300 字形）；安装包可带精简版字体或运行时从系统字体裁剪。
体积最优且字形正确；实现复杂度最高（字体解析 + 字形子集化 + cmap 重建，Rust 侧需 font 库）。
优势安装包与 PDF 体积都可控（release gate 无压力）；字形正确；后续新增生僻字也能覆盖（子集按需）。
代价实现最复杂（font parsing/subsetting，约 2–4 周量级 + 契约测试）；需要选定并审计一个 Rust 字体库（依赖面扩大）。
C
系统字体 fallback
PDF 引用系统 CJK 字体（不嵌入）；查看设备缺字体时 fallback 到座位号（v1 现状）。

零实现成本；但「PDF 发给家长看不了名字」正是 v1 已知缺陷（ledger 登记），与 v2 质量目标冲突。

代价跨设备（家长/打印店）姓名不可见——v1 已知缺陷延续；与「CJK PDF 姓名必须可读」约束冲突，不推荐。
