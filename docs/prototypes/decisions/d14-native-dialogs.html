Decision D14 · ledger §14（PYTHON_ONLY 原生对话框）

原生文件对话框：Tauri 原生对话框 vs 前端 input 上传/下载

真实任务：教师选择本地 CSV 名单导入、选择导出文件保存位置。v1 pywebview 用系统原生对话框；v2 桌面壳是 Tauri（有原生对话框 API），Web 工作台只能用浏览器 input。

不可违反约束：Web 工作台（浏览器）不可能调用系统对话框——任何方案都必须保证 Web 端可用（input 上传/下载）；v2 final 移除 pywebview；文件读写路径保持 Rust 侧校验（路径逃逸防御等已实现）。
A
Tauri 原生对话框
桌面端（Tauri 壳）导入/导出使用系统原生打开/保存对话框；Web 端回退到浏览器 input。

桌面端体验与 v1 pywebview 一致（教师习惯）；文件路径由 Tauri dialog 返回、Rust 侧校验后读取。
Tauri 壳通过 dialog API（tauri-plugin-dialog）提供；Web 端同一按钮回退到 <input type="file">（能力探测驱动）。
优势桌面体验与 v1 一致；系统对话框的目录导航/最近文件/收藏天然可用；保存路径选择直观。
代价桌面/Web 双路径需统一封装（能力探测）；Tauri 插件依赖 + 权限清单维护；E2E 测试中系统对话框自动化成本高。
B
前端 input 上传/下载
导入用浏览器文件选择（input + drag-drop），导出走浏览器下载（保存到默认下载目录）。桌面与 Web 行为一致。

桌面与 Web 完全一致的路径；导出文件进入系统下载目录（可后续移动）；无需任何原生插件。
v2 Web 工作台现状即此（无原生对话框）。
优势单一实现路径（桌面/Web 一致）；无 Tauri 插件依赖；E2E 自动化简单（input 可编程触发）。
代价桌面端无系统对话框（教师选「下载目录」再移动文件）；与 v1 pywebview 体验有差异；大目录导航不便。
