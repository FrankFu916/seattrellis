设计要点说明
按问题组织① 为什么推荐 A（理由卡，2–3 句通俗话）→ ② 差多少（差异高亮 + 一行通俗差异）→ ③ 想深究（明细切换）→ ④ 雷达图为可选视图。非四块拼图
去术语化（G-1）程序术语 → 通俗文案（i18n message_key 资产，与 Rust audit suggested_actions 结构一致）：
fair_rotation→轮换公平性 · avoid_recent_neighbors→避免和近期同桌/邻座再相邻 · score_balance→成绩搭配 · height_back→高个子靠后 · vision_front→视力需求靠前 · diversity→方案多样 · stability→与上期变动幅度 · hard_constraint_summary→硬性要求
复现信息（G-3）seed / solver / build / 规则版本 / history range / candidate id 在「详情」折叠区可查，随导出元数据携带——通俗化不破坏复现契约
schema/API 影响无新 API；推荐理由文案模板在 application 层定义（复用 audit 报告）；i18n 资产表
