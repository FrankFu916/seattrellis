Decision D1 · 计划 §7.1 项 1

班级主导航：单页工作台 / 步骤向导 / 侧栏工作区

真实任务：教师打开班级 「初二（3）班」（20 人 · 教学楼 302），要完成「期中调座」——查看当前座位、修改规则、重新生成方案、确认并导出。三种方案都要让教师在不迷失的情况下完成这一连串操作。

不可违反的约束：React 普通流程必须完全绕过 Python（M2）；导入/保存/迁移/编辑的事务语义在 Rust 层冻结，UI 只决定呈现与触发方式（§7.5）；现有主流程（v1.9.x）不得因导航重构回退（§4.5）。

代价新手容易迷失「下一步该做什么」；长流程（导入→排座→导出）缺乏线性指引；Tab 过多时顶部拥挤。

提示：未配置历史快照时，「公平轮换 / 避免近期邻座」维度将显示为不可用。可返回第 1 步补交。
向导尾部常驻「上一步 / 下一步」，每步校验由 Rust 契约执行，不允许带错进入下一步。
优势线性心智模型，新手零学习成本；与「导入→排座→导出」事务流程天然对齐；适合首次使用与演示场景。
代价老手频繁调参会感到繁琐（每步都要走）；跨领域对照（如边看结果边改规则）需要额外「分屏」支持。
