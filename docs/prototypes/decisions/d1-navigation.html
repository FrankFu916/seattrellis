班级主导航 — 融合方案：侧栏骨架 + 上下文操作条 + 临时工作台

真实任务不变：教师打开「初二（3）班」完成期中调座；多班级教师日常切换；偶尔一次性排座。C 方案（侧栏）为骨架，吸收 A 的单页直达与 B 的引导性，覆盖新手/老手、单/多班级、一次性排座全部场景。

不可违反约束：React 主流程完全绕过 Python（M2 §5.7）；导入/保存/迁移/编辑事务语义冻结于 Rust（§7.5）；v1.9.x 主流程不回退（§4.5）；临时排座与长期管理不得形成两个产品概念（§7.4，G-5）。

来自 B上下文操作条给出"下一步"；首次任务清单提供线性引导，用过即收
来自 C侧栏承载多班级管理 + 临时工作台（一次性排座，保存后升级为正式班级）
设计要点说明
临时工作台无项目上下文：上传名单 → 教室 → 规则 → 排座 → 导出或「另存为班级」。对应 v1 workspace 语义（§7.4 / G-5）
简单/复杂轮换按期数渐进披露：1 期 = 单次排座；多期 = 轮换计划。不另开产品形态
模式策略不做显式新手/老手开关；可选「密度设置」（紧凑/标准）待原型验证
schema/API 影响无新 API；路由需支持"班级上下文 + 临时工作台上下文"；临时工作台复用现有 import/solve/export 端点

待验证（dogfood）：

  • 密度设置（紧凑/标准）是否保留
  • 临时工作台 → 正式班级的保存转换流程
  • 首次任务清单的触发条件（无历史数据）与收起时机
