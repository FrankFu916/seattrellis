Decision D2 · 计划 §7.2

Seating canvas：缩放拖拽 / 框选批量 / 表格直编

真实任务：教师对「初二（3）班」已生成方案做局部调整——把 2–3 名学生挪到更合适的位置，同时保证 学生丁001 的固定座位（R1C1）不可移动。三个变体都演示同一场景。

结果能力（§7.2，全部变体必须满足）：大教室快速定位/缩放/移动；单选、多选、批量移动；锁定/违规/未入座/选中状态明确可见；非法操作提交前可识别；所有持久编辑必须走 Rust editing 协议命令，undo/redo 不因 UI 重构破坏；键盘可完成核心操作。
体验对比：三种方案的差异只在「如何完成这些操作」，最终选择由本决策的可用性验证决定。
A
缩放 + 拖拽（单座）
画布式：缩放/平移视图，按住座位直接拖到目标座位（自动交换）。参考 SeatingChartEditor2 的交互家族。
localhost:8765/class-302/canvas
100% 固定：学生丁001
拖拽座位到另一座位 → 交换（Rust editing: swap） 就绪
试一下：拖动任意普通座位到相邻座位，观察交换；锁定座（紫色）不可拖。
优势最直观的「空间」心智模型；与真实教室布局一致；缩放解决大教室定位问题（§7.2 能力 1）；交互家族成熟有参照。
代价精确「放到第几排第几列」需要缩放操作成本；触控/键盘等价实现工作量最大；拖拽误操作率需 dogfood 验证（§7.2 Canvas Decision Gate）。
B
框选 + 批量移动
鼠标拖出选框，批量选中后整体移动或执行批量操作（交换/锁定/标记）。
localhost:8765/class-302/canvas
已选 0 座 固定：学生丁001
在空白处按住拖出选框 → 批量选中；选中后可整体操作 就绪
试一下：从座位区空白处拖出选框；点选单个座位可切换；已选座位可「锁定」批量操作。
优势批量调整效率最高（整排整块移动、统一锁定）；选择状态可视化清晰；与「锁定/批量标记」工作流契合。
代价「框选」手势对触控/键盘不友好，需另配选择模式；单座微调比 A 多一步；批量操作的 undo 粒度（单命令 vs 多命令）需定义。
C
表格直编
座位以「排 × 列」表格呈现，每个单元格下拉选择学生；筛选与排序在表头完成。
localhost:8765/class-302/table
视图：表格 🪑 画布 固定：学生丁001
座位学生标签状态
每格下拉选择一个学生；非法选择（重复/违规）在提交前提示 就绪
试一下：任选一格更换学生；固定座（R1C1）的下拉被禁用。
优势实现最简单可靠；键盘可达性最好（Tab + 方向键）；与名单数据对照直观；无障碍（屏幕阅读器）成本最低。
代价丧失「空间感」——教师看不到教室结构（讲台/窗/门）；大班（60 人）滚动查找效率低；§7.2 的「快速定位」能力需额外筛选支持。
