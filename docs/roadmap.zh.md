# 产品路线图

[English](roadmap.md) · [简体中文](roadmap.zh.md)

SeatTrellis 2.0 已经建立了“本地优先”的产品基础。本文说明下一阶段的投入方向以及必须遵守的隐私边界；它是方向性规划，不代表具体发布日期承诺。

## 2.0 已交付

- CLI、本地 Web 服务与 Tauri 桌面端共用的 Rust 求解核心。
- 覆盖名单导入、教室布局、规则配置、多方案比较、手工调整和多期轮换的教师工作流。
- 八种本地导出格式：HTML、打印 HTML、SVG、PNG、PDF、XLSX、DOCX 和 PPTX。
- 确定性求解、结构化诊断、项目备份与面向公开场景的隐私导出。
- 以英文为默认语言、通过 GitHub Pages 静态部署的文档站。

## 近期优先方向

1. **增强布局编辑**：框选、批量移动座位、更好的触控操作和异形教室布局向导。
2. **座次变化可视化**
   - **已交付**：生成时座位移动热力图，覆盖完整生成序列的座位占用变化、当前布局能解析两个座位 ID 时的相邻轮次移动距离，以及汇总统计。占用变化来自生成时快照，距离使用当前布局坐标；随后的手工微调不会更新热力图，也不会改写这些快照。
   - **仍待完善**：邻座历史关系图，以及更清晰的候选方案与轮次对比。
3. **Web 分发技术验证**：在不削弱隐私承诺的前提下，验证浏览器本地 WebAssembly 运算路径。
4. **无障碍与响应式体验**：完善键盘操作、屏幕阅读器语义、减少动态效果和小屏平板布局。
5. **桌面端正式签名**：在发布者基础设施具备后引入 macOS 公证与 Windows 签名。

## Web 部署与隐私架构

文档站是纯静态内容，可以安全部署在 GitHub Pages、Vercel、Netlify 或 Cloudflare Pages。应用工作台则不同：它目前调用仅监听本机回环地址的 Rust API，因此直接把现有 `dist` 上传到静态托管平台，只会得到一个没有求解后端的界面。

### 首选方向：浏览器本地 WebAssembly

WebAssembly 版本最符合 SeatTrellis 的隐私模型。静态界面与求解器可以由上述任一平台分发，而学生名单和项目文件始终留在用户浏览器内。

技术验证应当做到：

- 通过 WebAssembly 暴露范围窄、带版本号的求解、校验和导出接口；
- 在 Web Worker 中运行耗时计算，避免阻塞界面；
- 默认只在内存中保存输入，IndexedDB 持久化必须由用户明确选择；
- 禁用遥测、远程日志和第三方分析；
- 配置严格的内容安全策略，并用自动化测试阻止意外网络请求；
- 明确浏览器可支持的导出格式，因为文件系统和系统字体能力需要浏览器专用实现。

这条路线仍有实际开发成本：部分 crate 当前依赖原生线程、文件系统、系统字体或服务端 API。应先完成一个端到端的小型求解切片，再承诺完整功能和格式对齐。

### 备选方向：短生命周期云端计算

Vercel、Netlify 和 Cloudflare 可以托管界面与短生命周期计算，但学生数据会进入第三方服务器，信任边界因此发生变化；GitHub Pages 本身不能提供这种后端。若采用云端计算，必须具备逐请求隔离、经过认证且不可猜测的标识、仅内存处理、禁用请求正文日志、严格的大小与时间限制、立即清理以及公开的数据保留政策。“计算后删除”只能降低留存风险，不能等同于本地计算。

因此，云端计算不是默认路线。对于明确接受并能够自行控制该边界的组织，自托管 Rust 服务仍然是合适选择。

## 工具链策略

Web 应用已使用 TypeScript 7，并通过类型检查、单元测试和浏览器 E2E 验证。Docusaurus 文档站会继续使用 TypeScript 6，直到其工具链正式支持 TypeScript 7。单独升级文档编译器几乎没有用户可见收益，因此兼容性优先于版本完全统一。

## 明确不做

- 集中存储学生数据或强制用户账号体系。
- 第三方广告、行为分析或商业遥测。
- 把“服务端处理后删除”宣传成与浏览器本地计算等价的隐私保证。
