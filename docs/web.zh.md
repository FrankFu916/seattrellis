# Web 端使用指南

## 推荐入口：React 工作台

```bash
python -m pip install -e ".[web,excel,image]"
seattrellis workspace
```

React 工作台是普通教师的默认入口，覆盖名单导入、字段映射、名单直接编辑、教室模板、自定义
排数和列数、走廊与不可用座位、常用排座目标、组合偏好、相邻/固定座位要求、
生成、可视化编辑教室、座位交换、撤销/重做、导出和班级项目备份。生成页的“高级设置”包含
求解器参数和完整 rules JSON；旁边的“详细排座规则”面板则用表单提供已实现的历史轮换、
邻座回避、成绩位置/均衡和互助搭档设置。`groups` 可以通过 JSON 配置组内必须相邻或
不得相邻，`cooling` 仍可兼容保存，但后端会提示它尚未参与求解。

## Streamlit 兼容与高级入口

```bash
python -m pip install -e ".[web,excel,image,pdf,docx]"
streamlit run src/seattrellis/web/app.py --server.address 127.0.0.1
```

本文后续的“教师工作台”“高级工具”和“Project workspace”主要描述 Streamlit
兼容页面。它仍然保留 preset、rules overlay、历史目录、候选数量、seed、时间限制、
backend 和细粒度导出隐私设置，旧的 JSON/Project/CLI 工作流不需要迁移。

## Streamlit 教师工作台

Streamlit 页面默认显示教师工作台，普通教师不需要准备 layout、rules 或 Project JSON：

1. 填写班级名称并导入 CSV、XLSX 或 XLSM 名单；只有姓名列也能开始，也可以在名单编辑器中
   直接添加或修正学生资料。
2. 接受自动推荐的 30、48 或 60 座教室，或者填写排数、每排座位数、走廊和不可用
   座位。
3. 选择日常轮换、快速打乱或邻座互助，同时勾选视力、身高、历史轮换等偏好，并
   添加不能相邻、必须相邻或固定座位的要求。
4. 查看推荐座位图，按需换座、锁定、撤销或重做。
5. 准备并下载公开打印版或教师打印版。

侧边栏切换到“高级工具”后，仍可使用原有两个标签页：

- **快速排座**：按“加载数据 → 配置与求解 → 查看结果”三步操作，支持一键
  Demo、layout、preset、rules overlay 和多份历史 snapshot。
- **Project workspace**：本机 Project 路径可用于校验、求解和导出；单独上传
  project JSON 只做格式校验和配置预览。

左侧栏的“语言 / Language”可在简体中文和英文之间切换。切换语言只改变界面
文字，不会清空已加载的数据、当前步骤或求解结果。教师工作台返回后会恢复解析过
的名单、教室、目标和方案，但不会保留原始上传文件字节；“重新开始并清除名单”
只清除教师工作台，不影响高级工具。

生成前会明确提示当前缺少哪些可选的历史、成绩、身高或视力信息；只有姓名列时仍
可使用“快速打乱”。

“生成”步骤还可以一次生成未来多期轮换。填写期数，并可用逗号或换行设置期次名称；
每一期都有独立的编辑草稿，点击摘要中的期次即可载入原有的调整和导出流程，同时显示
全部期次和重复邻座摘要。

### 详细排座规则

如果常见偏好还不够精确，可以在“生成”步骤展开“详细排座规则”。这里可以设置历史回看
期数、近期邻座的关系类型和距离、高分靠前或靠后、按排或小组均衡成绩，以及互助搭档的
高低分位。权重属于软目标，“两人不要相邻”等硬性要求仍然优先。按小组均衡时，需要在
layout 座位上提供 `group_id`。完整 RuleSet 可继续通过 rules JSON 使用，但 cooling 的
model-only 状态会在后端提示。

### React 工作台的班级项目面板

使用 `seattrellis workspace` 时，排座流程旁边会显示“班级项目”面板。输入本机
目录并刷新后，程序会查找 `*.project.json` 和 `*.seattrellis.json`。选择班级后，
页面只显示历史文件和生成文件的元数据，不会把学生记录或成绩作为这部分响应发送到
浏览器。

面板支持检查项目中的敏感字段、比较两个历史或生成文件、从选中的方案创建新的当前
方案快照、下载 `.seattrellis.zip` 备份，以及把上传的项目包恢复到本机目录。比较接口
除了座位变化数量、名单变化数量和布局/规则状态，还可以展开查看匿名编号及前后座位；不会
把学生姓名或学号、成绩发送到浏览器。
恢复操作只写入新的 outputs 文件，不会覆盖原始历史文件。浏览器上传和 CLI 使用同一套
路径安全与 manifest 校验。教室编辑器已经可以在普通流程中修改网格、走廊、讲台和空位；
学生资料编辑已可在名单步骤中完成，已实现的软规则可以在详细规则面板中编辑。完整的
RuleSet 可视化编辑器（包括 cooling 和迁移辅助）仍在后续路线中。

## Rules 预览

进入“设置与求解”后，页面会显示 preset 与 rules overlay 合并后的完整
`RuleSet`。可以在求解前核对 hard rules、权重和 seed，也可以下载合并后的
JSON 留档。

## History 质量检查

上传 history 后可以运行质量检查。报告按 snapshot 显示：

- 当前学生覆盖率；
- 缺失学生和不在当前名单中的学生；
- 未知座位和已禁用座位；
- snapshot layout 是否与当前 layout 一致。

Demo 会自动加载 `examples/history/` 中的虚构历史记录。

## Project workspace

输入本机 Project 文件路径后，可以读取配置、校验引用文件、求解候选方案并导出。
单独上传的 project JSON 只包含清单，浏览器无法同时取得它引用的学生、layout、
rules 和 history 文件，因此页面只会安全校验并显示配置，不会解析其中的服务端
路径，也不会启用求解或导出。React 工作台的班级项目面板则提供最近项目、历史元数据、
隐私检查以及 `.seattrellis.zip` 备份和恢复。

## 保存和恢复设置

“下载当前 Web 配置”会保存 preset、rules overlay、候选数量、seed 和时间限制。
该文件不包含学生名单、layout、history、路径或求解结果。需要注意，fixed
seat、pair rule 和 group 等规则可能引用学生 ID；页面检测到这类字段时会显示
隐私提示。恢复配置后仍需加载本次使用的数据文件。

## 结果与导出

多候选结果可以切换预览，并在同一张表中比较总分、hard constraints 和七个评分维度。座位图、评分明细和分配表会随候选切换同步更新。

页面提供导出模板与隐私设置面板，可以选择公示版、教师内部版或候选解释报告，
并配置匿名化、字段隐藏、A4 横纵向、缩放和中英文内容。模板的安全默认值只能
进一步收紧；公示版不会因取消某个选项而暴露敏感字段。

页面可下载 snapshot/candidate set、plan report、HTML、打印 HTML、PDF、PNG、
Excel 和 Word。缺少 optional extra 时会显示对应安装提示，不影响其他格式。

## 锁定与局部重排

求解后展开“锁定与局部重排”，可以锁定学生当前位置、锁定座位，并选择只允许
重新安排的受影响学生。若不选择受影响学生，系统会在保留锁定的前提下执行全局
重排。快速排座会继续使用本次加载的 history；Project 工作区会使用项目配置的
history 目录。重排完成后页面会显示实际改变座位的学生，并把锁定状态和调整摘要
写入新 snapshot 的 metadata。

后端可以选择 `auto`、`fallback`、`ortools` 或实验性的 `native`。`native` 仅供
同版本源码树中的构建测试，不随 PyPI 主包或任何 extra 安装；`auto` 不会自动
启用它。普通安装应使用 `auto`、`fallback` 或 `ortools`。

## 人工交换与撤销

求解后展开“人工调整”，可以交换两名学生、把学生移动到空座、移入未入座区，或
把未入座学生重新安排到空座。移动操作只接受空座，不会静默把目标座位上的第三名
学生移出。每次调整都会立即复核当前 `RuleSet` 的 hard constraints，并在结果区
明确显示通过状态或违规数量。操作按顺序写入草稿，可以连续撤销和重做；当前草稿
可直接导出，也可以作为“锁定与局部重排”的输入继续自动修复。

人工调整不会改写原始候选集或 rules 文件。输出 snapshot 的 `metadata.manual_edit`
会保存操作、锁定状态、未入座学生和约束检查摘要，便于审计调整来源。

“锁定状态”区域可以直接锁定或解锁已入座学生及任意启用座位。被锁定学生不会
出现在可移动学生列表中，被锁定座位也不会作为移动目标；占用锁定座位的学生同样
不能交换或移出。锁定与解锁都是可撤销操作，并写入 `metadata.lock_state`。随后
执行局部重排时，“沿用快照中已保存的锁定”会自动继承这些状态。

“批量移动”按选择顺序把多名学生与多个目标座位一一配对，并在执行前显示配对
预览。学生数与座位数必须相同；可以把所选学生的当前座位作为目标形成轮换，但不能
挤走批次外学生。整个批次只形成一条操作记录，因此一次撤销即可完整恢复。

“座位图快捷操作”可以直接点击座位：在“移动 / 交换”模式下先点击已入座座位，
再点击空座完成移动，或点击另一名学生完成交换；再次点击起点会取消选择。在
“锁定 / 解锁座位”模式下，单击启用座位即可切换锁状态。锁定学生或锁定座位在
移动模式下会禁用，所有图上操作仍会写入同一命令日志并执行 hard constraint 诊断。

## 隐私与临时文件

所有求解均在本机完成。教师结果被替换或清除时，其已注册的临时工作目录会立即
删除；其余 Web 中间目录会在进程退出时清理。Project 路径模式会访问用户填写的
本机路径，因此不要把该 Streamlit 服务开放给不受信任的网络用户。不要把真实
学生数据、截图或导出文件提交到公开仓库。

## 键盘与小屏使用

- 按 Tab 可依次访问上传、选择、求解和下载控件，焦点位置会用蓝色轮廓标出。
- 页面开头提供“跳到主要内容”链接，键盘用户可以略过侧栏和重复导航。
- 座位图中的启用座位可以用 Tab 聚焦；辅助技术会读出座位、学生和位置标签。
- 窄屏下并排控件会自动改为纵向排列，按钮保留至少 44 像素的触控高度。
- 操作系统开启“减少动态效果”后，页面会停用非必要动画。

## 当前限制

- 教室编辑器目前使用点击和工具栏操作，尚未提供拖拽或框选 layout 编辑。
- 学生资料编辑已可在名单步骤中完成；规则编辑器仍在后续路线中。
- 历史方案比较和从历史创建新 snapshot 已支持，跨方案逐项可视化差异仍会继续完善。
- 当前支持座位图点击与表单操作，尚未提供框选或拖拽。
- Streamlit 的表格在很窄的手机屏幕上仍可能需要横向滚动。
- 当前只提供简体中文和英文。
