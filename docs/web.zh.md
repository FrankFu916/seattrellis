# Web 端使用指南

[English](web.md) / [简体中文](web.zh.md)

SeatTrellis v2.0.0 的 Web 工作台由纯 Rust 的本地服务提供。

## 启动工作台

v2.0.0 的网页工作台由纯 Rust 的 `seattrellis_web` 本地服务提供。它只绑定本机回环
地址（默认 `127.0.0.1:8765`），启动时生成 256-bit 会话 token，并自动在浏览器
中打开 React 工作台：

```bash
seattrellis_web --open-browser
# 或
cargo run -p seattrellis_web -- --open-browser
```

桌面应用（Tauri 壳）内部就是启动同一个服务并在原生窗口中加载工作台。开发时
可用 `SEATTRELLIS_WEB_STATIC` 覆盖嵌入的前端资源目录。服务只在本机监听，
不要把它暴露到局域网或不信任的网络环境。

## React 工作台

React 工作台是普通教师的默认入口，覆盖名单导入、字段映射、名单直接编辑、教室
模板、自定义排数和列数、走廊与不可用座位、常用排座目标、组合偏好、相邻/固定
座位要求、生成、可视化编辑教室、座位交换、撤销/重做、导出和班级项目备份。
生成页的"高级设置"包含求解器参数、历史 snapshot、完整 rules JSON 和 layout
JSON 的导入/下载；旁边的"详细排座规则"面板用表单提供已实现的历史轮换、邻座
回避、关系冷却、成绩位置/均衡和互助搭档设置。常见的命名小组可以直接在普通设置
中配置成员尽量相邻或保持分开；更复杂的组关系仍可通过 JSON 兼容入口配置。

教师工作台流程：

1. 填写班级名称并导入 CSV、XLSX 或 XLSM 名单；常见的无表头导出会保留第一行
   数据并提示确认姓名/学号列，只有姓名列也能开始，也可以在名单编辑器中直接
   添加或修正学生资料。
2. 接受自动推荐的 30、48 或 60 座教室，或者填写排数、每排座位数、走廊和
   不可用座位。
3. 选择日常轮换、快速打乱或邻座互助，同时勾选视力、身高、历史轮换等偏好，并
   添加不能相邻、必须相邻、固定座位、最小距离或小组关系的要求。
4. 查看推荐座位图，按需换座、锁定、撤销或重做。
5. 选择公示版、教师内部版或方案报告，检查隐私字段和 A4 缩放后预览并下载。

左侧栏的"语言 / Language"可在简体中文和英文之间切换。切换语言只改变界面文字，
不会清空已加载的数据、当前步骤或求解结果。教师工作台返回后会恢复解析过的名单、
教室、目标和方案，但不会保留原始上传文件字节；"重新开始并清除名单"只清除教师
工作台。

生成前会明确提示当前缺少哪些可选的历史、成绩、身高或视力信息；只有姓名列时仍
可使用"快速打乱"。

"生成"步骤还可以一次生成未来多期轮换。填写期数，并可用逗号或换行设置期次名称；
每一期都有独立的编辑草稿，点击摘要中的期次即可载入原有的调整和导出流程，同时
显示全部期次和重复邻座摘要。

### 详细排座规则

如果常见偏好还不够精确，可以在"生成"步骤展开"详细排座规则"。这里可以设置历史
回看期数、近期邻座和冷却期的关系类型与距离、高分靠前或靠后、按排或小组均衡
成绩，以及互助搭档的高低分位。权重属于软目标，"两人不要相邻"等硬性要求仍然
优先。按小组均衡时，需要在 layout 座位上提供 `group_id`。完整 RuleSet 仍可
通过 rules JSON 使用。

### 班级项目面板

排座流程旁边会显示"班级项目"面板。输入本机目录并刷新后，程序会查找
`*.project.json` 和 `*.seattrellis.json`。选择班级后，页面只显示历史文件和
生成文件的元数据，不会把学生记录或成绩作为这部分响应发送到浏览器。

面板支持检查项目中的敏感字段、比较两个历史或生成文件、从选中的方案创建新的
当前方案快照、下载 `.seattrellis.zip` 备份，以及把上传的项目包恢复到本机目录。
比较接口除了座位变化数量、名单变化数量和布局/规则状态，还可以展开查看匿名编号
及前后座位；不会把学生姓名或学号、成绩发送到浏览器。恢复操作只写入新的 outputs
文件，不会覆盖原始历史文件。面板里的"项目格式迁移"会先按当前 schema 检查项目
主文件或历史/输出文件。默认写入新的 `.migrated.json` 文件；只有明确勾选原地迁移
时才会替换原文件，并自动保留 `.bak` 备份。浏览器上传和 CLI 使用同一套路径安全
与 manifest 校验。

教室编辑器可以在普通流程中修改网格、走廊、讲台和空位；学生资料编辑已可在名单
步骤中完成，常见小组关系和已实现的软规则可以在普通设置或详细规则面板中编辑。
高级设置中的自定义 RuleSet JSON 会显示字段级检查，能在生成前指出不支持的字段、
格式错误的硬约束、名单或座位引用错误；规则编辑器覆盖四类 hard rule、已实现
soft rule 和命名小组，另外仍保留原始 JSON 兼容入口。历史 snapshot 可一次选择
多个文件，直接参与公平轮换和近期邻座计算。

如果当前工作区已经生成了多期轮换并且选择了一个班级项目，面板还会显示"保存到
班级项目"，把所有期次的当前座位、锁定状态和编辑操作保存为新的轮换计划输出，
不会覆盖原文件。历史或输出中已有轮换计划时，项目面板还可以"继续编辑轮换"，
重新创建各期编辑草稿，再回到座位图继续调整。

对已保存的轮换计划，面板还可以生成小组登记表：选择可打印的 HTML 或可在表格
软件中继续处理的 CSV。登记表按期次列出小组、学生、座位和状态，并明确保留空组、
未入座学生及名单中不存在的成员。下载前还可以先查看成员变化预览，按期次显示
小组人数、入座状态以及相邻期次的新增/移出统计；预览不在浏览器中显示姓名和学号。
项目格式迁移预览会列出字段路径和类型变化、迁移前后校验状态及备份/回退提示，
不会显示学生姓名、成绩或其他原始字段值。

## Rules 预览

进入"设置与求解"后，页面会显示 preset 与 rules overlay 合并后的完整 `RuleSet`。
可以在求解前核对 hard rules、权重和 seed，也可以下载合并后的 JSON 留档。

## History 质量检查

上传 history 后可以运行质量检查。报告按 snapshot 显示：

- 当前学生覆盖率；
- 缺失学生和不在当前名单中的学生；
- 未知座位和已禁用座位；
- snapshot layout 是否与当前 layout 一致。

Demo 会自动加载 `examples/history/` 中的虚构历史记录。

## Project workspace

输入本机 Project 文件路径后，可以读取配置、校验引用文件、求解候选方案并导出。
单独上传的 project JSON 只包含清单，浏览器无法同时取得它引用的学生、layout、
rules 和 history 文件，因此页面只会安全校验并显示配置，不会解析其中的服务端
路径，也不会启用求解或导出。React 工作台的班级项目面板则提供最近项目、历史
元数据、隐私检查以及 `.seattrellis.zip` 备份和恢复。

## 保存和恢复设置

"下载当前 Web 配置"会保存 preset、rules overlay、候选数量、seed 和时间限制。
该文件不包含学生名单、layout、history、路径或求解结果。需要注意，fixed seat、
pair rule 和 group 等规则可能引用学生 ID；页面检测到这类字段时会显示隐私提示。
恢复配置后仍需加载本次使用的数据文件。

## 结果与导出

多候选结果可以切换预览，并在同一张表中比较总分、hard constraints 和评分维度。
座位图、评分明细和分配表会随候选切换同步更新。

页面提供导出模板与隐私设置面板，可以选择公示版、教师内部版或候选解释报告，
并配置匿名化、字段隐藏、A4 横纵向、缩放和中英文内容。模板的安全默认值只能
进一步收紧；公示版不会因取消某个选项而暴露敏感字段。

页面可下载 snapshot/candidate set、plan report、HTML、打印 HTML、PDF、PNG、
Excel 和 Word。所有格式都由本地 Rust 渲染器生成，不依赖任何可选安装包。

## 锁定与局部重排

求解后展开"锁定与局部重排"，可以锁定学生当前位置、锁定座位，并选择只允许
重新安排的受影响学生。若不选择受影响学生，系统会在保留锁定的前提下执行全局
重排。快速排座会继续使用本次加载的 history；Project 工作区会使用项目配置的
history 目录。重排完成后页面会显示实际改变座位的学生，并把锁定状态和调整摘要
写入新 snapshot 的 metadata。

## 人工交换与撤销

求解后展开"人工调整"，可以交换两名学生、把学生移动到空座、移入未入座区，或把
未入座学生重新安排到空座。移动操作只接受空座，不会静默把目标座位上的第三名
学生移出。每次调整都会立即复核当前 `RuleSet` 的 hard constraints，并在结果区
明确显示通过状态或违规数量。操作按顺序写入草稿，可以连续撤销和重做；当前草稿
可直接导出，也可以作为"锁定与局部重排"的输入继续自动修复。

人工调整不会改写原始候选集或 rules 文件。输出 snapshot 的 `metadata.manual_edit`
会保存操作、锁定状态、未入座学生和约束检查摘要，便于审计调整来源。

"锁定状态"区域可以直接锁定或解锁已入座学生及任意启用座位。被锁定学生不会出现在
可移动学生列表中，被锁定座位也不会作为移动目标；占用锁定座位的学生同样不能交换
或移出。锁定与解锁都是可撤销操作，并写入 `metadata.lock_state`。随后执行局部
重排时，"沿用快照中已保存的锁定"会自动继承这些状态。

"批量移动"按选择顺序把多名学生与多个目标座位一一配对，并在执行前显示配对预览。
学生数与座位数必须相同；可以把所选学生的当前座位作为目标形成轮换，但不能挤走
批次外学生。整个批次只形成一条操作记录，因此一次撤销即可完整恢复。

"座位图快捷操作"可以直接点击座位：在"移动 / 交换"模式下先点击已入座座位，再点击
空座完成移动，或点击另一名学生完成交换；再次点击起点会取消选择。在"锁定 / 解锁
座位"模式下，单击启用座位即可切换锁状态。锁定学生或锁定座位在移动模式下会禁用，
所有图上操作仍会写入同一命令日志并执行 hard constraint 诊断。

## 隐私与临时文件

所有求解均在本机完成。教师结果被替换或清除时，其已注册的临时工作目录会立即
删除；其余工作目录会在进程退出时清理。Project 路径模式会访问用户填写的本机
路径，因此不要把该服务开放给不受信任的网络用户。不要把真实学生数据、截图或
导出文件提交到公开仓库。

## 键盘与小屏使用

- 按 Tab 可依次访问上传、选择、求解和下载控件，焦点位置会用蓝色轮廓标出。
- 页面开头提供"跳到主要内容"链接，键盘用户可以略过侧栏和重复导航。
- 座位图中的启用座位可以用 Tab 聚焦；辅助技术会读出座位、学生和位置标签。
- 窄屏下并排控件会自动改为纵向排列，按钮保留至少 44 像素的触控高度。
- 操作系统开启"减少动态效果"后，页面会停用非必要动画。

## 当前限制

- 教室编辑器目前使用点击和工具栏操作，尚未提供拖拽或框选 layout 编辑。
- 历史方案比较和从历史创建新 snapshot 已支持，跨方案逐项可视化差异仍会继续完善。
- 当前支持座位图点击与表单操作，尚未提供框选或拖拽。
- 当前只提供简体中文和英文。
