# SeatTrellis v2 — 触控 Decision Gate 决策记录（计划 §7.2）

> 日期：2026-08-12
> 状态：**已决策**
> 决策人：产品负责人（席序 v2）
> 依据：总计划 §7.2（"触控支持是否作为 v2 final 必须项，由原型测试
> Decision Gate 决定"）、UI 设计方向 §5（手势行：macOS 触控板捏合缩放 /
> 其余 Ctrl+滚轮）、§6（触控目标 ≥44px，座位块为内容豁免）。

## 1. 结论

**触控（触屏设备）不作为 v2 final 必须项**。v2 final 以桌面三平台
（macOS / Windows / Linux，Tauri 桌面壳 + 浏览器 Web 工作台）为准，
触屏使用为**降级可用**（可点选、可拖拽、不可捏合），完整触控体验
（双指缩放、触控滚动消歧、44px 目标审计、平板实机验证）登记为
**M7 打磨候选**，不作为 alpha/beta 阻断。

## 2. 依据（原型测试与现状评估，2026-08-12）

1. **目标场景**：课堂排座是教师端工具，真实使用发生在桌面设备
   （教室电脑/笔记本 + 投影）；设计方向 §5 的平台表也只有"触控板
   捏合"（macOS trackpad 手势），从未承诺触屏支持。
2. **触控就绪度审计**（原型形态即当前实现）：
   - 画布已全部使用 **Pointer Events**（onPointerDown/Move/Up），
     mouse/pen/touch 统一路径，触控点选与拖拽天然可用；
   - 本次补齐 `touch-action: none`（画布手势移动座位而非滚动页面）
     与 **Ctrl+滚轮缩放**（macOS trackpad 捏合在浏览器层映射为
     ctrl+wheel，一个处理器同时覆盖设计方向 §5 的两种手势）；
   - 缩放范围 0.6–1.8 由单一纯函数 `nextCanvasZoom` 定义（工具栏
     按钮与手势共用，测试覆盖）。
3. **未满足的完整触控项**（均为 M7 候选）：双指捏合事件的自定义
   处理（ctrl+wheel 在触屏 WebView 中不产生）、触控滚动与拖拽的
   手势消歧、≥44px 触控目标全组件审计、真机（iPad/触屏 Win）验证。
4. **代价对比**：完整触控 = 手势消歧 + 目标审计 + 双平台真机测试，
   对 alpha.2（关闭 parity gap）与 beta（M6 Python 退休）是净负收益；
   降级可用已覆盖"临时用触屏看一眼"的偶发场景。

## 3. 降级可用清单（本次已实现，C3 交付）

| 能力 | 触屏现状 |
|---|---|
| 点选座位 / 激活诊断徽章 | ✅ Pointer Events，tap 即用 |
| 拖拽交换 / 批量移动 | ✅ Pointer Events + `touch-action: none` |
| 缩放 | ✅ 工具栏按钮；桌面手势（ctrl+wheel / trackpad 捏合）本次实现 |
| 表格视图（非拖拽替代路径，§6） | ✅ 触屏友好（滚动容器 + 36px 行） |
| 双指捏合 / 触控滚动消歧 | ⏳ M7 候选，v2 final 不阻断 |

## 4. 决策影响登记

- 无 Rust / schema / 契约影响（纯 UI 手势层）。
- UI 设计方向 §5 手势行：macOS 触控板捏合 = ctrl+wheel 已实现；
  其余平台 Ctrl+滚轮 = 同一处理器。
- M7 候选清单新增：完整触控（双指缩放 + 触控目标审计 + 真机验证）。
