# SeatTrellis v2 — 内嵌示例名单草案（D10 待研究项落地）

> 日期：2026-08-10
> 状态：**草案**——D10 决策（内嵌任务 + 示例名单兜底）的示例名单内容研究。
> 示例名单是应用内嵌静态资产（Rust 或前端嵌入，非 CLI 命令——与 D15
> 移除 init-demo 不冲突）；带「示例」隔离标记、删除即清零（§7.4）。
> 关联：PD-D10-ONBOARDING、G-5（临时工作台语义）、parity fixture 数据
> 资产（data-unicode 等）。

## 1. 设计目标

「极其简单且恰到好处」的定义（评审要求）：示例名单要让新教师在 **5 分钟
内走完 完整流程**（导入 → 规则 → 生成 → 导出），且：
- 名单本身不引入理解负担（无生僻字、无奇怪数据）；
- 属性丰富度足够演示常见规则（视力前排、身高靠后、成绩搭配、固定座位）；
- 规模小（≤30 人），生成/渲染即时完成；
- 与真实数据完全隔离（标记 + 一键删除）。

## 2. 内容设计（候选）

### 规模：20 人（5×4 教室正好满座——无空座干扰，且够演示）

### 字段覆盖（对应 roster 全字段，让映射/预览路径完整演示）

| 字段 | 设计 |
|---|---|
| student_id | `S01`–`S20`（简单、可读） |
| name | 中文姓名：**常见姓氏 + 常见名**（张伟/王芳/李娜/刘洋…，无生僻字） |
| gender | 男女均衡（10/10） |
| height_cm | 130–180 均匀分布（演示「高个子靠后」） |
| score | 55–98 均匀分布（演示「成绩搭配」） |
| vision | 3 人 `0.6`、1 人 `poor`（演示「视力需求靠前」） |
| tags | 2 人 `leader`（演示标签规则） |
| needs | 4 人 `vision_front`（与 vision 字段联动演示） |
| notes | 2 人备注（如「家长会关注」——演示 hide_notes） |

### 配套资产（示例班级 = 名单 + 教室 + 规则）

| 资产 | 设计 |
|---|---|
| 教室 | 标准 5×4（20 座，与名单满座）——与 parity fixture `data-unicode`
  布局同构，渲染路径零额外测试面 |
| 规则 | 1 条 hard（固定座位：张伟 → R1C1）+ 2 条 soft（视力前排 weight 20、
  高个子靠后 weight 10）——演示 D3 句式模板 |
| 预设方案 | 不预置（引导流程就是"生成第一个方案"） |

### 命名与隔离

- 班级名：「示例班级」；所有界面显示「示例」徽章（D10 页面已设计）；
- 数据存储：独立于真实班级的命名空间（`sample://` 前缀或独立目录），
  删除示例 = 删除该命名空间全部内容，不影响任何真实数据；
- 导入真实名单后示例仍可保留（对照学习）或一键删除。

## 3. 为什么这样设计（对应目标）

| 设计选择 | 理由 |
|---|---|
| 20 人满座 | 生成/导出即时（性能无感）；无空座干扰新手理解 |
| 常见姓名 | 教师代入感强（vs fixture 的「学生丁001」式生成名） |
| 属性完整但克制 | 每类属性恰好够演示一条规则，不堆砌 |
| 无生僻字/无特殊需求 | "恰到好处"= 新手不因示例数据本身产生疑问 |
| 与 fixture 布局同构 | 渲染/求解路径复用已验证的测试面 |

## 4. M5 实现约束

1. 示例名单作为**静态资产**嵌入（Rust include_str! 或前端资产），构建时
   校验（字段完整性、20 人、无重复 id）——防资产腐化；
2. 「示例」隔离命名空间与删除语义（§7.4）进入验收清单；
3. 示例名单不进入 fixtures/parity（那是 oracle 语料，语义不同）；如需
   复用，单独登记资产来源；
4. 与 D15 无冲突：不提供 `init-demo` 命令，示例仅 UI 内嵌资产。

## 5. 待 dogfood 验证

- 新手 5 分钟完整流程达成率；
- 「示例」徽章与删除语义的误操作率（是否有人误删真实数据——预期 0）；
- 示例名单是否需要「换一批」功能（不同班级规模示例）——初始不做，验证
  后决定。
