# SeatTrellis v2 — UI 设计方向草案（M4 收口 · G-6 落地）

> 日期：2026-08-10
> 状态：**方向草案**——设计原则与平台策略在 M4 收口时确定，约束 M5 实现；
> 像素级细节（具体尺寸、间距刻度、动效曲线、组件变体）不在本文件冻结，
> 随 M5 组件实现 + dogfood 迭代（计划 §0.5：交互细节经原型验证后冻结）。
> 依据：Apple HIG 平台无关设计哲学 + 批 2 决策记录 G-6（专业、简洁、易用、
> 无 AI 味）+ 已冻结决策 D1–D15。

## 1. 设计哲学：Apple HIG 四支柱 × 跨平台中性

本项目是 **Web 优先 + 三平台（macOS/Windows/Linux，计划 §17.5）**。不整体
照搬 Apple HIG 控件规范（SF Symbols、材质、毛玻璃不可跨平台一致实现），
而是提取其**平台无关设计哲学**四支柱，作为一切视觉与交互决策的判据：

| 支柱 | 含义 | 在本产品的落点 |
|---|---|---|
| **清晰 Clarity** | 信息层级一目了然，不被装饰干扰 | 语义色系统（红=违规/黄=建议/绿=满足，不另造含义）；术语通俗化（G-1）；密度优先 |
| **遵从 Deference** | 内容优先，界面让位于数据 | 座位表/名单是主角；无装饰性渐变、玻璃拟态、花哨阴影；画布空白充足 |
| **克制 Restraint** | 只保留必要元素与动效 | 动效仅做状态反馈（拖拽跟随是功能反馈，非装饰）；默认面板只问 3 个问题（D4）；「导出」一次点击（D9） |
| **深度 Depth** | 空间/层级关系真实可感 | 画布的空间心智模型（D2 拖拽整块跟随）；候选差异高亮（D5）；诊断徽章与座位空间绑定（D6） |

**判据**：任何 UI 决策过四问——① 是否让信息更清晰？② 是否让内容更突出？
③ 是否足够克制？④ 是否尊重空间/层级真实感？四问任一为否，回到 G-6。

## 2. 与已冻结决策的映射（实现约束）

| 决策 | 设计含义（M5 必须遵守） |
|---|---|
| D1 导航 | 侧栏骨架 + 上下文操作条；首次任务清单用过即收；临时工作台与班级同构（无"第二产品"观感） |
| D2 画布 | 拖拽整块跟随（drag-lift）；框选批量；表格视图为同一状态的投影；**动效仅限拖拽跟随与状态高亮，无装饰动画** |
| D3 规则 | 句式构建器（自然语言）+ 卡片管理 + 高级表单兜底；JSON 只读查看（代码视图用等宽字体、深色底，与主界面区分） |
| D4 快速/高级 | 默认 3 问 + 历史范围可见；折叠区展开不带动画（或 ≤120ms 淡入） |
| D5 候选 | 推荐理由卡（通俗话）→ 差异高亮 → 明细切换；术语映射表 i18n；复现信息收"详情"折叠 |
| D6 诊断 | 徽章 + 列表双向联动；修复动作即时反馈（validator 复核结果可见） |
| D7 历史/轮换 | 双视图切换无过渡动画（标签页式切换）；周期卡片并排 |
| D8 导入 | 步骤条 + 同屏映射/预览；原子确认栏明确显示"可回滚" |
| D9 导出 | 快速导出菜单 + 默认值矩阵；「版式与隐私设置」为同一面板的分层（非两套 UI） |
| D10 引导 | 内嵌任务卡 + 示例名单兜底；任务卡完成态打勾（语义色），无庆祝动画 |
| D11 print | 打印版式为独立资产：深色文字白底、无背景色依赖、无交互元素（规范另文） |
| D12 PDF 字体 | 系统字体智能引用；字体质量警告为文本提示（非弹窗动画） |
| D13 PNG | 位图渲染姓名；匿名化打码样式与界面语义一致（"学生A/B/C"） |
| D14 文件选择 | 三入口统一为同一"文件选择"组件；拖拽高亮为边框反馈（语义色） |
| D15 遗留 | 无遗留命令 UI |

## 3. 视觉基调（方向约束，非像素冻结）

- **配色**：以语义色为核心——状态色固定含义（红=违规/错误、黄=建议/警告、
  绿=满足/成功、紫=锁定、青=选中）；品牌色仅用于主要操作按钮与当前态。
  深色/浅色主题（计划 §17.4 UI/E2E 含 dark/light）在 M5 以同一语义色 token
  实现，**不得为暗色主题另造含义**。
- **字体**：系统字体栈（-apple-system / Segoe UI / Noto Sans CJK / PingFang
  SC / Microsoft YaHei），与 D12"系统字体智能引用"同一哲学——不打包字体；
  等宽字体（ui-monospace）仅用于代码/JSON/seed 等技术信息（G-3 复现信息）。
- **间距与层级**：8pt 基准间距刻度；层级用留白与字重表达，不靠阴影堆叠；
  阴影仅用于浮层（菜单/弹窗/拖拽中的元素）。
- **圆角与控件**：统一小圆角（4–8px 级）；按钮/输入框全平台一致高度；
  图标单套跨平台（Material Symbols 风格线性图标），macOS 壳内可替换 SF
  Symbols（平台自适应，见 §5）。
- **密度**：标准密度为默认（列表行高 ≥40px 触控友好）；"紧凑"为可选设置
  （D1 待验证项），不做第三种密度。

## 4. 动效与反馈原则

1. **动效只做状态反馈**：拖拽跟随（D2）、选中高亮、修复完成提示、导入
   应用完成。不做装饰性动画（无渐入渐出秀、无骨架屏弹跳、无庆祝粒子）。
2. **时长 ≤200ms**，仅 transform/opacity 属性（性能与克制并重）。
3. **减少动效**：系统"减弱动态效果"偏好必须尊重（macOS Reduce Motion /
   Windows 动画设置——Tauri 壳可探测，Web 用 `prefers-reduced-motion`）。
4. **状态变化必须有非动画通道**：语义色 + 图标 + 文本并存（色弱/无动画
   用户不丢失信息）。

## 5. 平台自适应策略（M5 实现层，Tauri 壳知道平台）

| 维度 | macOS | Windows / Linux | Web（浏览器） |
|---|---|---|---|
| 快捷键 | Cmd 系 | Ctrl 系 | 按宿主平台（浏览器无法探测时用 Ctrl + 提示） |
| 文件对话框 | 系统对话框（D14，Tauri dialog） | 同左 | 拖拽 + input（D14） |
| 图标 | 可换 SF Symbols | Material 风格单套 | 同单套 |
| 手势 | 触控板（捏合缩放画布） | 鼠标滚轮 + Ctrl | 同 Windows |
| 窗口 | Tauri 原生 | 同左 | 浏览器标签页 |

**原则**：产品观感三平台一致（同一布局/配色/组件）；平台惯例（快捷键/
手势/对话框）跟随宿主。**不得**为 macOS 单独设计一套布局或交互。

## 6. 无障碍与键盘（计划 §7.2 能力 + §17.4）

- 全交互键盘可达：Tab 顺序 = 视觉顺序；画布核心操作（移动/锁定/撤销）
  有键盘等价（方向键移动选中、⌘Z/Ctrl+Z 撤销）。
- 对比度：正文/背景 ≥ 4.5:1（WCAG AA）；语义色不单独承载信息（配图标/
  文本）。
- 焦点可见：聚焦态用 2px 品牌色描边（跨平台一致）。
- 触控目标 ≥ 44px（画布座位块除外——座位块是内容不是控件，点击命中
  区域放大）。
- 屏幕阅读器：座位图为表格语义（`role="grid"` 等价物），名单为 table；
  拖拽操作提供非拖拽替代（D2 表格视图即无障碍路径）。

## 7. 反模式清单（"AI 味"红线，M5 code review 检查项）

- 装饰性玻璃拟态/毛玻璃（除了 macOS 菜单栏等系统层）
- 渐变按钮/渐变背景装饰
- 无意义的悬浮卡片/漂浮动画
- emoji 作为产品图标（界面内），emoji 仅允许出现在用户内容/占位示例
- 千篇一律的"现代 SaaS 紫/蓝渐变"配色
- 动效装点（弹跳、弹簧、粒子）
- 文案使用营销腔/过度友好语气（保持教师语境的专业平实）

## 8. M5 实现约束条款

1. 本文件为设计方向约束，M5 组件实现必须逐条对照；偏差需在 PR 说明理由。
2. 像素级 token（精确尺寸/间距刻度/动效曲线/主题色板）在 M5 首个组件批次
   落地时以本方向为准制定，经 dogfood 后冻结（G-4 证据要求）。
3. 深色主题与"减少动效"尊重要求进入 M5 验收清单（§17.4）。
4. 键盘与无障碍要求进入每个交互组件的验收清单。
5. 本草案的修订需过设计评审（决策人确认），不得在实现中悄然偏离。
