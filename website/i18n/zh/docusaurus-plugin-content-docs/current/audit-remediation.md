其他修复包括有限数值与成本溢出、轮换种子安全加法、按需图距离、准备阶段的截止时间/取消、按真实期次的历史回溯、pack/restore 一致限制、bundle 保留名、受根限制且防软链接循环的项目列表、原子唯一恢复/轮换命名、CLI 历史转发、导出设置持久化、XLSX 表头本地化、HTML 完整可访问分配表、Word 实际分页。部分软规则 JSON 现在使用模型声明的默认值，避免误用零值。

保存的轮换期次先使用捕获的源上下文，再考虑当前项目输入，避免后来修改名单或换成无效规则导致完整旧计划无法重开。嵌入网页资源复制到不可变构建目录，避免前端再次构建后旧文件名失效。排他创建文件要求硬链接支持；文件系统或权限不支持时明确报错并保留目标，避免有竞争条件的覆盖回退。在 FAT/exFAT 或受限挂载上使用项目之前，应测试此能力。

输入明确限制身高 0–300 cm、分数 ±1e9；最多 1000 名学生、10000 座位、100000 条边/硬约束。图距离操作另限 2000 座位，以约束矩阵内存。这些校验拒绝不现实或消耗过量资源的输入。旧结果可省略可选成本字段，但已提供的非有限成本被拒绝。

两套 npm 依赖已修补并采用零 advisory 例外策略。删除失效的 Python benchmark 与 PyInstaller spec。现用性能脚本记录独立冻结输入、哈希与机器/编译器元数据，限制子进程时间，不再声称与 Rust 长跑生成器相同或完全消除计时噪声。

## 验证记录

本机集成验证通过 802 项 Rust 测试（常规运行排除 8 项需显式开启的测试）、272 项前端测试及全部 8 项真实 Chromium 流程，严格 workspace Clippy 通过。另行运行 release 候选、长跑及轮换门禁，涵盖 500 次重复求解、植入合法解语料、取消和逐期独立验证。六个 fuzz 目标各完成 3000 次有界运行，未报告失败；这属于有限验证，不代表穷尽覆盖。本机缺少平台库，workspace 编译排除了 Tauri crate。

生成契约检查、12 项发布/安全工具测试及 Actionlint 通过。两套 npm 树报告零漏洞；cargo-deny 按仓库现有策略通过，其中仍有明确记录的 Rust advisory 例外。云代理拒绝默认数据库抓取，因此使用 Git CLI 获取 advisory 数据库，未放宽策略。前端和双语文档的类型检查与构建均通过。推送后仍需查看远程系统矩阵与发布 CI 的实际结果。

CLI 性能门禁通过未改动的相对与绝对阈值；本机 40/50/60/80 人中位耗时为 142.93/286.97/660.90/2207.31 ms。修订后的输入显式保留默认值修复前实际测量的纯硬约束任务，未改写计时基线；缺少历史机器元数据仍限制跨机器比较。

独立的[求解器对比](https://github.com/FrankFu916/seattrellis/tree/main/benchmarks/solver-comparison)保存九组案例及 27 次试验，36 份合法输出均通过两种验证器；构造的不可行案例另有独立图证明。CP-SAT 在该纯硬约束语料上更快，支持进一步开发可选后端；未认证加权质量、移动分发或替代 C++ 实现。耗时与限制见[技术决策](technology-decisions.md)。

本机独立阅读器已覆盖七组 40/60 人、横/竖向、显示/隐藏编号和 25 mm 边距，均为一页且保留全部姓名。测试使用 LibreOfficeDev 26.8 与 Poppler；Microsoft Word/WPS 仍需目标阅读器验收。
